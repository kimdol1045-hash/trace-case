# 2026 과거 QA CSV corpus 프로파일

## 목적과 범위

사용자가 제공한 모바일 POS, POS 어드민, StoreX QA 완료 CSV 세 파일을 향후
자동 생성의 팀 작성 스타일·회귀 예시 corpus 후보로 분석했다. 원본은 UTF-8 CSV이며
quoted multiline cell을 보존해 읽었다. 이 단계에서는 QA 보드 DB로 이관하거나 원본을
repository에 복사하지 않았다.

## 구조 요약

| corpus | 논리 행 | 결과 포함 후보 행 | 열 수 | ticket-like 식별자 |
|---|---:|---:|---:|---:|
| 모바일 POS | 13,306 | 12,132 | 12 | 43 |
| POS 어드민 | 2,976 | 2,838 | 14 | 10 |
| StoreX | 4,523 | 4,319 | 17 | 65 |
| 합계 | 20,805 | 19,289 | — | 중복 제외 약 116개 구간 |

후보 행은 `Pass`, `Fail`, `확인불가` 등 실행 결과가 하나 이상 있는 행이다. StoreX는
한 케이스 행에 플랫폼별 결과 열이 여러 개 존재하므로 후보 행 수와 결과 slot 수가
같지 않다. Jira key는 원본 구간 파악에만 사용하며 새 자동 생성 입력이나 QA 보드
식별자로 사용하지 않는다.

## 공통 작성 형태

세 corpus의 공통 의미 구조는 다음과 같다.

```text
일감 또는 배포 구간
  → 메뉴·화면 경로
  → 검증 항목
  → 짧은 확인 문장
  → QA 상태·플랫폼별 결과·비고
```

- 경로형 텍스트가 있는 후보 행은 16,264건이다.
- multiline cell을 포함한 후보 행은 4,507건이다.
- `확인` 표현은 13,940개 후보 행에 나타난다.
- `정상`, `노출`, `입력`, `저장`, `등록`, `조회`, `변경`이 반복되는 간결한 검증 문장이
  팀의 주된 스타일이다.
- POS 어드민은 동일한 엑셀 열·언어·다운로드 검증 문구가 대량 반복된다.
- 모바일 POS는 앞부분의 `경로·항목` 2열형과 뒤의 `경로·항목·내용` 3열형이 한 파일에
  섞여 있어 파일 전체에 고정 column index를 적용할 수 없다.
- StoreX는 경로·항목·내용 뒤에 여러 플랫폼 결과 slot과 비고가 이어진다.

## QA 보드와의 매핑

| 과거 CSV 의미 | 새 QA 보드·생성 pipeline |
|---|---|
| Jira key·URL | 수집 구간 파악 후 제거; Slack 일감이 source와 상위일감 기준이다. |
| 경로 | category exact·alias·semantic 후보와 기능 검색 query로 사용한다. |
| 항목 | 테스트케이스 서머리 후보와 기능 묶음 기준으로 사용한다. |
| 확인 문장 | 검증 목적·동작·기대결과 예시로 사용하되 Slack/RAG에 없는 사실은 채택하지 않는다. |
| 작성자·QA·개발 담당자 | 익명화하고 생성 context에서 제외한다. |
| 플랫폼별 Pass/Fail/확인불가 | 과거 실행·회귀 위험 feature로 사용하며 케이스 본문으로 복사하지 않는다. |
| 비고 | 과거 결함·환경 제약 후보로 사용하고 근거 상태를 판별한 뒤에만 생성에 반영한다. |

대부분의 과거 행에는 현재 QA 보드가 요구하는 스텝별 사전조건과 실행 순서가 명시돼
있지 않다. 따라서 이 corpus는 문장 스타일, 검증 관점, 중복·회귀 탐지에 적합하지만
그 자체를 완성된 보드 케이스 정답으로 사용하지 않는다. 실제 스텝은 Slack 요구사항과
현재 `ACTIVE` RAG 근거를 사용해 작성한다.

## 자동 작성 규칙에 반영할 사항

1. 기본 출력은 기능 묶음별 5~10개다. 넓은 일감은 기능을 나눠 여러 generation batch로
   생성하며 전체를 10개로 자르지 않는다.
2. 경로와 항목이 같고 확인 문장이 동일·유사한 행은 exact+semantic cluster로 묶는다.
3. 대량 반복된 generic 문구는 빈도가 높다는 이유로 우선순위를 올리지 않는다.
4. 과거 `Fail`·`확인불가`·비고는 회귀 후보지만 현재 Slack/RAG 근거와 연결된 경우에만
   케이스로 생성한다.
5. 기존 문장의 간결한 `...되는지 확인` 스타일은 서머리·기대결과 문체 참고로 사용하되,
   현재 보드에는 관찰 가능한 결과를 평서문으로 명확하게 저장한다.
6. 플랫폼 열은 `WEB/AOS/IOS` label·실행 히스토리로 정규화하고 불명확한 slot을 임의로
   플랫폼에 배정하지 않는다.

## 정제 gate

- Unicode NFKC, 공백, `>`, `/`, `＞` 경로 구분자를 정규화한다.
- 사람 이름, Jira URL/key, 날짜, 주문·고객 식별값을 제거하거나 가명화한다.
- exact duplicate와 near duplicate를 분리하고 source row hash로 재현성을 남긴다.
- 현재 케이스 원장과 충돌하면 과거 CSV가 아니라 현재 `ACTIVE` version을 우선한다.
- 학습·검색 dataset과 parser/generation 품질 평가 dataset을 분리해 data leakage를 막는다.
