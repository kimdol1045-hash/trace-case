## 변환 규칙

- 헤더의 외부 일감 키 행은 상위일감으로 변환하고 시스템 키는 `WORK-*` 형식을 사용했다.
- `경로`의 첫 구간은 도메인으로, 나머지 구간은 라벨로 변환했다.
- `항목`은 하나의 테스트케이스가 된다.
- 같은 항목에 반복된 `내용`은 순서를 유지한 여러 테스트 스텝이 된다.
- 각 스텝은 `사전조건 → 테스트 동작 → 기대결과`로 재작성했다.
- 원본의 담당자, QA 상태, Pass·확인불가와 실제 장애 메모는 과거 실행 기록이므로 새 라이브러리 케이스에 넣지 않았다. 실행 결과는 새 사이클에서 기록한다.
- 의미가 명확한 오탈자 `세금 정구`, `주문 록록`, `옵셥`과 중복 문장은 각각 `세금 청구`, `주문 목록`, `옵션`과 단일 문장으로 정규화했다.

## 안전장치와 재사용

- 이관 전 PostgreSQL 전체 덤프와 활성 R2 첨부 원본을 `/private/tmp/tc-pre-csv-import-20260825`에 저장하고 SHA-256을 확인했다.
- 활성 목 첨부는 백업 후 API 삭제를 거쳐 R2 원격 객체 삭제 성공을 확인했다.
- [CSV 이관 스크립트](../../scripts/import_test_cases_csv.py)는 기본이 dry-run이며, 실제 초기화에는 `--apply --confirm RESET-DEMO-DATA`를 모두 요구한다.
- 활성 첨부가 남아 있으면 R2 고아 객체를 만들지 않도록 초기화를 거부하며, 먼저 API 백업·삭제 절차를 거쳐야 한다.
- 초기화 범위는 운영 데이터 테이블로 한정하고 `workspace_settings`, `ontology_schemas`, `alembic_version`은 보존한다.
