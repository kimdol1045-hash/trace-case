# 화면 네비게이션 정책

브라우저 뒤로가기의 의미를 보존하고, 생성·삭제가 끝난 임시 화면이 history에 남지 않도록 화면 전환을 아래와 같이 고정한다. 구현 원장은 [`navigation-policy.ts`](../apps/web/src/navigation-policy.ts)다.

| 출발 화면 | 도착 화면 | 방식 | 이유 |
|---|---|---|---|
| Dashboard / 목록 | 테스트·사이클·이슈 상세 | Stack (`push`) | 뒤로가기로 사용자가 보던 목록과 필터로 복귀 |
| 테스트·사이클·이슈 목록 | 생성 화면 | Stack (`push`) | 취소 또는 뒤로가기로 원래 목록에 복귀 |
| 생성 화면 | 취소 후 목록 | Replace | 취소한 임시 폼으로 다시 돌아오지 않음 |
| 생성 화면 | 생성된 상세 | Replace | 뒤로가기로 이미 완료된 생성 폼에 재진입하지 않음 |
| 사이클 상세 | 실행 화면 | Stack (`push`) | 뒤로가기로 같은 사이클 상세에 복귀 |
| 실행 화면 | 연결 이슈·라이브러리 원본 | Stack (`push`) | 실행 맥락을 history에 보존 |
| 상세 | 저장 성공 | 현재 route 유지 | 수정은 새 화면이 아니라 같은 리소스의 새 버전 |
| 상세 | 삭제 성공 후 목록 | Replace | 삭제된 상세 화면으로 되돌아가지 않음 |
| legacy/alias route | canonical route | Replace | 같은 화면을 가리키는 중복 history 제거 |
| 모달 열기/닫기 | 동일 route | history 미사용 | 사이클 범위·이슈 생성 모달은 화면 route가 아닌 일시 UI 상태 |

## 적용 규칙

- `Link`로 여는 목록→상세, 상세→연관 리소스는 기본 Stack 전환을 사용한다.
- 프로그램 전환은 의미가 드러나는 `appNavigationOptions`를 사용하고 화면에서 `replace` 값을 임의로 지정하지 않는다.
- 저장 실패, 버전 충돌, 입력 오류는 이동하지 않고 현재 화면에 오류를 유지한다.
- 생성 성공 후 첨부 저장만 실패한 경우에는 생성 폼을 유지해 생성된 이슈 상세로 갈 선택지를 제공한다. 사용자가 상세를 열 때는 생성 폼을 Replace한다.
- 목록의 검색어·상태 필터를 URL query로 승격하는 후속 변경 전까지는 명시적 “목록” 링크를 제공하고 브라우저 Back은 기존 stack을 따른다.
